# Repository Agent Guidance

## Scope

This repository implements a focused Go SDK for three distinct Vercel AI Gateway surfaces: the AI SDK provider-protocol Evaluation Model V4 endpoint, public `/v1/responses`, and public `/v1/chat/completions`, including the documented streaming subsets. Read `planning/IMPLEMENTATION_PLAN.md` before implementation and follow its dependency order, evidence gates, acceptance checks, and commit boundaries. Do not broaden the project into a generic OpenAI client, infer undocumented fields/tools, or claim parity with the JavaScript AI SDK.

## Lessons

- The evidence baseline recorded on 2026-09-20 is `ai@7.0.107`, `@ai-sdk/gateway@4.0.87`, `@ai-sdk/provider@4.0.17`, and `@ai-sdk/provider-utils@5.0.45`. Evaluation entered `ai` in 7.0.103 and Gateway evaluation entered `@ai-sdk/gateway` in 4.0.85. Re-check these versions and upstream source before changing the wire contract.
- The official `@ai-sdk/gateway` provider protocol is not the public OpenAI-compatible `/v1` API. Its default base URL is `https://ai-gateway.vercel.sh/v4/ai`.
- Evaluation Model V4 uses `POST /v4/ai/evaluation-model`. The model ID is carried in `ai-model-id`, not in the JSON body. Required protocol headers include `ai-gateway-protocol-version: 0.0.1`, `ai-evaluation-model-specification-version: 4`, and `ai-gateway-auth-method: api-key|oidc`.
- The evaluation JSON body contains one shared JSON-compatible `state`, a nonempty keyed `questions` map, and optional `providerOptions`. Supported question/answer variants are boolean, choice, and score. The contract includes response validation, optional rounding, usage, warnings, provider metadata, and response metadata.
- `POST https://ai-gateway.vercel.sh/v1/evaluate` is a separate public REST surface whose body includes `model`. It remains unimplemented and evidence-gated because the public success presence/nullability/extension contract is not sufficiently proven. Do not conflate it with provider-protocol `Evaluate` or route it through Chat/Responses.
- Authentication precedence modeled from the official provider is explicit API key, `AI_GATEWAY_API_KEY`, then OIDC when no API key is available. An explicitly selected API key is not silently replaced by OIDC after server rejection. OIDC needs a refresh-capable token source for long-lived clients.
- Model IDs are dynamic `provider/model` strings. A live provider-protocol evaluation on 2026-09-21 confirmed `typesafe-ai/jev`; the previous `typesafe-ai/jev-latest` now returns HTTP 404 `model_not_found`. The SDK must accept arbitrary nonempty IDs instead of freezing a closed enum.
- Direct xAI Responses (`POST https://api.x.ai/v1/responses`) and `@ai-sdk/xai@5.0.4` are separate provenance for the `x_search` vocabulary and provider-executed `x_search_call` items; never treat that direct-provider contract as evidence for Vercel AI Gateway behavior or validation.
- Vercel AI Gateway Responses support is request-only for fixed low-context `{"type":"web_search","search_context_size":"low"}`, separate fieldless `ResponseXSearchTool`, and `ResponseXSearchOptionsTool`'s six exported fields: `AllowedXHandles`, `ExcludedXHandles`, `FromDate`, `ToDate`, `EnableImageUnderstanding`, and `EnableVideoUnderstanding` (wire keys `allowed_x_handles`, `excluded_x_handles`, `from_date`, `to_date`, `enable_image_understanding`, and `enable_video_understanding`). Owner-authorized evidence on 2026-09-21 clears only the exact tested singleton, neutral empty-list/explicit-false, and allowed/excluded maximal five-field forms on `spacexai/grok-4.6`; arbitrary subsets remain unresolved, and simultaneous non-empty allowed/excluded lists are rejected locally. Preserve outputs and events raw; infer no semantics, limits, date behavior, wider model support, wrong-kind behavior, or direct-xAI compatibility. Retain no credentials, prompts, generated prose, raw payloads, or sensitive artifact text in repository evidence. Chat request-only declarations for `vercel:exa_search`, `vercel:parallel_search`, `vercel:perplexity_search`, and `vercel:tako_search` remain a separate opt-in surface whose typed outputs, metadata, lifecycle events, and live corroboration are evidence-gated.
- Evaluation is experimental and may change in patch releases. Pin hermetic fixtures to cited upstream versions and keep releases at v0 while the contract is unstable. Claims of live evaluation compatibility require separately authorized live evidence; the owner-directed initial experimental release explicitly retains the pending-live limitation.
- Default retries must remain off because evaluation may be billable and is not known to be idempotent. If callers opt in, retry only classified transient failures with bounded backoff, Retry-After support, and immediate context cancellation.
- Prefer a boring design: one root `gateway` package, small internal HTTP/test helpers, standard library first, private wire DTOs, no JavaScript monorepo mirroring, no automatic tool execution, and no generic cross-surface generation or tool abstraction.
- The current repository/module identity is `github.com/EveGoodEvening/v-ai-go-sdk`; the root package remains `gateway`. The implemented public boundary includes provider-protocol `Client.Evaluate`, public Responses and Chat methods, the request-only Chat server-tool methods for four supported `vercel:*` declarations, and opt-in Responses built-in-tool methods for exact fixed low-context `web_search`, fieldless `x_search`, and the exact Gate-A-cleared configurable `ResponseXSearchOptionsTool` forms. Public Evaluate, arbitrary configurable subsets, other web-search forms, typed search outputs/events, wider model compatibility, semantic or limit claims, date behavior, wrong-kind behavior, and direct-xAI support remain absent and evidence-gated.
- Provider-protocol evaluation and public generation use distinct base URLs and configuration. `WithBaseURL` remains exclusively for `https://ai-gateway.vercel.sh/v4/ai`-style provider endpoints; `WithPublicBaseURL` configures the public `https://ai-gateway.vercel.sh/v1` Responses/Chat origin. Never repurpose one option for the other surface or add `/v4` protocol headers to public requests.
- Responses success decoding is intentionally raw unless a field has exact first-party evidence. Streaming types only the proven `response.output_text.delta` path; other bounded events stay raw. Hermetic handling of raw data or a build-tagged assertion is not proof of live event semantics.
- Chat compatibility uses its own request/result/stream types. Buffered documented fields preserve absent versus null versus value explicitly; streaming types only the proven text-delta subset and `[DONE]` termination. Unknown or undocumented fields remain bounded raw JSON rather than inferred typed support.
- Paid live evidence remains separately authorized and independently reviewed. The owner-directed initial experimental publication on 2026-09-30 proceeds with the general live suites explicitly disclosed as NOT RUN, not falsely cleared. A credential-free fail-closed test, hermetic fixture, compile, static workflow review, or published version never establishes live success. Public-generation and provider-evaluation jobs retain distinct acknowledgement sentinels, pinned models, and sanitized evidence.
- Keep README concise: an API overview, one runnable quick start, and guide links; leave per-method limits and exhaustive non-goals in linked documentation. Shared user-facing authentication, endpoint, retry, error, cancellation, and privacy guidance belongs in `docs/client.md`; README and the generation/evaluation guides link there instead of duplicating it. Keep operator checklists and pending hosted evidence in the release/live-evidence docs, not in the quick start. Documentation snippets should compile and use structural-only output; validate them with loopback fixtures rather than paid calls.
- Streaming methods bypass the SDK `RetryPolicy` loop entirely; they do not just disable retries after headers. HTTP execution borrows the configured client's transport, cookie jar, and timeout but overrides redirect handling to return redirects without following them. Ground shared documentation in all implemented surfaces rather than evaluation-only error-operation inventories.
- Across supported Go toolchains, `encoding/json` can encode each invalid UTF-8 byte as escaped `\ufffd` (six bytes) or literal U+FFFD (three bytes), and `json.RawMessage` can reflect as its alias target `jsontext.Value`. Exact request-size preflight must follow the active encoder without per-request allocation; public field-contract checks must compare `reflect.Type` identity rather than `Type.String()` spellings.
- The owner delegated license selection and authorized tagging/publication on 2026-09-30; MIT is in root `LICENSE`. The owner then created `release` and explicitly directed publication without master protection, reviewers, or manual SHA approval. This later decision supersedes the historical manual release blockers, not the documented live-evidence limitations or authorization required for new paid calls.
- Tag releases reuse read-only pinned CI and publish automatically in the existing `release` environment. Do not reintroduce `RELEASE_APPROVED_SHA` or reviewer gates without an owner request. Release notes come only from an exact versioned changelog section with Migration notes; Unreleased is never a fallback. Direct-VCS and public-proxy consumers use separate caches and verify commit/checksums before execution; provenance attests their structural manifest, not Gateway success. A pushed tag exposes the Go version before GitHub Release creation.
- Isolated release-consumer checks need an installed Go toolchain with matching `PATH`/`GOROOT` and `GOTOOLCHAIN=local`. A fresh `GOMODCACHE` does not contain an auto-downloaded toolchain, and an inherited GVM `GOROOT` can pair a newer Go driver with older compiler tools. Local proxy fixtures disable sumdb only for their unpublished temporary module; the hosted release workflow explicitly uses `sum.golang.org`.
- License review on 2026-09-30 verified that the pinned `ai@7.0.107`, `@ai-sdk/gateway@4.0.87`, `@ai-sdk/provider@4.0.17`, and `@ai-sdk/provider-utils@5.0.45` npm metadata declares `Apache-2.0`; the [pinned upstream license](https://github.com/vercel/ai/blob/ai%407.0.107/LICENSE) identifies `Copyright 2023 Vercel, Inc.`. Root MIT licensing and a dependency-free `go.mod` do not establish that copied or translated upstream expression has no attribution obligations. Distinguish interface/behavior references from source adaptations; any distributed adaptations need review against [Apache-2.0 section 4](https://www.apache.org/licenses/LICENSE-2.0.txt), including license text, applicable notices, and modification notices. Open-source permissions do not replace Gateway service terms or grant trademark endorsement.
- The [Vercel brand guidelines](https://vercel.com/geist/brands), checked on 2026-09-30, permit truthful descriptive references but explicitly list using Vercel marks in a product/offering name as misuse; other uses require prior written permission. The owner chose `v-ai-go-sdk` to replace the former project title and personally renamed the GitHub repository. Keep non-affiliation wording and descriptive service references distinct from the independent project identity; an unofficial disclaimer alone is not a substitute for naming permission.
- The v0.2.0 source comparison attributes the source-driven input/JSON/answer validation portions in `evaluation_validate.go`, `jsonvalue.go`, and `evaluation_response.go` to the pinned upstream `validate-evaluation.ts`. Preserve the exact symbol/modification inventory in `THIRD_PARTY_NOTICES.md`, the full `LICENSES/Apache-2.0.txt`, and file-level notices. Other compared wire contracts, standard algorithms, and generic fixtures are reference-only findings, not blanket claims of copied expression or legal clearance; project-authored modifications remain MIT.
- The owner-authorized v0.2.0 rename changes module/import paths but not package `gateway`, APIs, endpoints, or behavior. Preserve `v0.1.0` and historical old-path evidence, migrate active consumers/workflows without aliases, and verify the owner-renamed repository's existing commit/tag continuity before updating local origin or publishing.
- Anonymous GitHub REST observation can exhaust its hourly quota while hosted CI is still running; an observer's HTTP 403 is not a workflow failure. Public workflow pages expose terminal status, the releases Atom feed exposes update times, and expanded-assets pages expose download links/SHA256 digests. A `/releases/tag/<version>` page alone is insufficient publication proof: GitHub can render a tag-only page with just two source archives before any GitHub Release exists. Require the actual release notes/assets and completed workflow, and label feed timestamps as updates rather than inventing REST `published_at` values.
- Public Go module ZIP inspection on 2026-10-01 confirmed that `v0.1.0` under the former module path contains the same three attributed validation implementations as new-path `v-ai-go-sdk@v0.2.0` (apart from the module rename) but lacks the Apache license copy, third-party inventory, and file-level adaptation/modification notices. The v0.2.0 ZIP includes those materials and the canonical Apache-2.0 text. Treat this as a historical redistribution compliance gap under the project's adaptation assessment; a corrected new release does not retroactively change old proxy archives. Preserve immutable tags and distinguish historical remediation from current-version notice checks.
- The [Vercel Terms of Service](https://vercel.com/legal/terms) introduction excludes software provided exclusively under open-source licenses, but hosted Gateway access remains separately governed by service/API/AI terms and provider policies. The [AUP](https://vercel.com/legal/acceptable-use-policy), checked on 2026-10-01, restricts using Services to develop similar/competing products and AI Services to build substantially similar functionality; [API Terms section 4](https://vercel.com/legal/api-terms) also restrict unauthorized performance testing and collection of end-user credentials. Official support for other clients/direct HTTP is not a blanket waiver, and neither a source-license review nor a successful request proves all development or service-use behavior compliant.
- Do not query public Go module services for a not-yet-pushed version as a pre-tag availability check. On 2026-10-01 that premature request cached `v0.2.1` as absent: direct Git resolved the correct tag, but `sum.golang.org` still returned `unknown revision` and blocked publication. The [Go module services FAQ](https://proxy.golang.org/) documents up to 30 minutes of negative caching. Check Git refs before tagging; after a confirmed propagation failure, wait for public visibility and rerun the unchanged failed job with checksum verification intact. Preserve `go mod download -json`'s `Error` and stderr; `CalledProcessError` alone loses the useful cause.
